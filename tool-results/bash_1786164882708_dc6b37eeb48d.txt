2. Website Audit
The website audit evaluates structural integrity, navigation, performance signals, and
mobile responsiveness. The Siva Pest Control site is built on Next.js 16 App Router with
a multi-page architecture: 10 static routes plus dynamic routes for services (7), locations
(3), and blog posts (6), totaling 26 URLs covered by an automatically-generated sitemap.
All routes were verified to return HTTP 200 with no runtime errors.
2.1 Site structure & navigation
The site has been correctly refactored from a single-page application (SPA) with hash-style views
to a true multi-page App Router architecture. Each major section (Services, Locations, Process,
Pest Library, Industries, Blog, FAQ, Contact, About) lives at its own URL with its own metadata,
and detail pages use Next.js's generateStaticParams + generateMetadata pattern for static
generation and per-page SEO. The legacy Zustand navigation store has been preserved as a
compatibility layer (via nav-bridge.tsx) so existing components continue to work, though new
components should use Next.js <Link> directly.
The desktop navigation bar offers a Services mega-menu (640px wide, glassmorphism) and a
Locations dropdown (420px wide), both hover-triggered. A potential overflow concern exists at
the 1024-1100px viewport range where the Services mega-menu could extend past the right edge
of the viewport if the trigger is positioned near the right side of the navbar. The mobile menu is
a right-side drawer with body-scroll lock and animated entrance. The footer is a comprehensive
5-column grid with brand info, contact methods, three navigation columns, plus a locations
strip and certifications bar.
2.2 Performance indicators
All images use next/image with the fill layout and explicit sizes attributes, which prevents layout
shift and enables automatic format negotiation. The hero image and the technician composition
image both use priority for Largest Contentful Paint (LCP) optimization. However, the
about-page hero and the blog detail article hero image do not use priority — these should be
added since they are the LCP element on their respective pages. The first three service cards on
the /services page are above the fold and should also use priority.
Framer Motion is used extensively for animations: scroll-reveal, staggered card entrances,
mouse-tilt 3D, particle drift, shield pulse, and city-pin connections. All whileInView animations
use viewport: { once: true }, preventing re-triggering on scroll-back. The hero's particle drift,
shield pulse, and city-pin connections run indefinitely, which could impact battery life on
low-end mobile devices. A <MotionConfig reducedMotion="user"> wrapper has been added to
the root layout in this audit pass, and the hero now conditionally skips the heavy animations
when prefers-reduced-motion is set.

3. SEO Audit
The SEO audit evaluates on-page factors, structured data, sitemap and robots
configuration, technical SEO signals, local SEO readiness, content quality, and
indexability. The site has a strong foundation — a PestControl JSON-LD schema, a
comprehensive sitemap, and proper metadataBase — but several critical issues were
identified and most have been fixed in this audit pass.
3.1 On-page SEO
Score: 5.5 / 10
Page titles use the template pattern %s · Siva Pest Control correctly, and each page has a unique
title. However, several page titles exceed the 60-character truncation point in Google SERPs (the
services page title was 75 chars, industries 72 chars, blog 72 chars). The home meta description
was 217 characters — well over the 150-160 optimal length. These have been shortened in this
audit pass. Image alt text is present on all images but often just repeats the title (e.g.,
alt={service.name}) rather than being descriptive; this should be improved for both accessibility
and image SEO.
Critical: Canonical URL bug (FIXED in this pass)
The root layout.tsx set alternates.canonical to the homepage URL, and no child page overrode it.
Next.js metadata merging caused every page to emit <link rel="canonical"
href="https://www.sivapestcontrol.com">, telling Google all sub-pages were duplicates of the
homepage. Sub-pages would have been dropped from the index. Fix applied: removed the root
canonical and added per-page canonical URLs to all 13 routes.
Internal linking was undermined by the use of <button onClick> for navigation in 11+
components. Search engine crawlers can follow sitemap discoveries, but in-page link discovery
is broken for blog posts, related services, related articles, and location detail CTAs. Each of these
should be converted to <Link href> with descriptive anchor text.
3.2 Structured data
Score: 5.0 / 10 (improved to 7.5 after this pass)
The root PestControl schema in layout.tsx is well-formed with name, address (3 cities), opening
hours, aggregateRating, hasOfferCatalog, and sameAs socials. However, several improvements
have been applied in this audit pass:
• Per-service Service schema added — Each /services/[slug] route now emits a Service
schema with name, description, provider, areaServed, offers (with INR price), and image.
• Per-service FAQPage schema added — Each service's FAQ section is now emitted as
FAQPage JSON-LD for rich-result eligibility.
• Per-blog-post BlogPosting schema added — Each /blog/[slug] route now emits
BlogPosting with headline, author, datePublished, image, publisher, and mainEntityOfPage.

4. UI/UX Audit
The UI/UX audit evaluates visual hierarchy, color system, layout, navigation,
interaction patterns, forms, mobile responsiveness, content messaging, animations,
and accessibility. The site has a strong premium visual identity with real photography,
glassmorphism cards, and a coherent warm-earth palette — but several accessibility
regressions and factual inconsistencies were identified.
4.1 Visual hierarchy & typography
Score: 7.5 / 10
Heading hierarchy is consistent: every page has exactly one <h1>, section headings use <h2> via
the SectionHeading component, and footer uses <h3> then <h4>. Display font Manrope is
correctly applied via the .font-display utility on all headlines; body uses Inter. The type scale is
coherent (h1 36-60px, h2 30-46px, body 16-18px). Section heading eyebrows use uppercase
tracking at tracking-[0.18em] which is unusually wide and can read as 'spaced out' at small sizes
on mobile. The hero h1 uses a gradient-clipped span ('scientifically delivered.') with no fallback
color set — if the gradient fails to render, the text becomes invisible.
4.2 Color system & contrast
Score: 7.0 / 10
The brand palette is centralized in globals.css and mapped to semantic tokens. Ivory
background (#F7F1E8) with deep brown text (#332416) achieves a contrast ratio of approximately
12.6:1 — well above WCAG AAA. However, several opacity-based colors fail WCAG AA for normal
text (4.5:1 minimum): text-brown/55 achieves only 3.4:1, text-brown/45 only 2.7:1, text-white/50
only 3.6:1 on dark backgrounds, and text-white/40 only 2.8:1. The orange CTA gradient
(linear-gradient(135deg, #E88521 0%, #B85C04 100%)) starts at #E88521 which yields only 3.3:1
contrast with white text — fails AA for normal text but is borderline AA-large due to
font-semibold. These should be bumped: text-brown/55 → text-brown/65, text-white/50 →
text-white/70, gradient start #E88521 → #D77005.
A 'dead' dark mode block exists in globals.css (20 lines of .dark token definitions) and the
sonner.tsx Toaster imports next-themes — but no <ThemeProvider> is ever mounted. Either
install a ThemeProvider or delete the dead tokens.

4.3 Navigation & wayfinding
Score: 6.5 / 10 (improved to 7.5 after this pass)
Navbar active state was color-only — no aria-current="page". Desktop mega-menus are
hover-triggered only (no focus handler), so keyboard users cannot open them. The mobile menu
was missing role="dialog", aria-modal, an Escape key handler, focus trap, and focus restoration
to the trigger button on close. Breadcrumbs in service-detail and location-detail pages used
<button onClick> instead of <Link>, missing aria-label="breadcrumb". The footer's Commercial
column has 5 links all pointing to /industries with different anchor text — a UX dead-end.
Fixes applied in this pass: aria-current="page" added to all navbar links (desktop + mobile);
mobile menu now has role="dialog", aria-modal="true", aria-label, an Escape key handler that
restores focus to the toggle button, and aria-controls + aria-expanded on the toggle button.
4.4 Interaction & feedback
Score: 6.5 / 10 (improved to 7.5 after this pass)
Hover states are extensively tuned (translate-y, shadow-lift, scale-1.02). The contact form has

6. Google Analytics 4 Integration
A complete, production-ready Google Analytics 4 (GA4) integration has been
implemented in this audit pass. The integration follows Google's recommended
patterns: lazy-loaded gtag.js, Consent Mode v2 with default-denied analytics storage,
automatic page-view tracking on App Router route changes, typed custom event
helpers for key conversions, and a privacy-first cookie consent banner with
localStorage persistence.
6.1 Architecture
The integration consists of four files:
• src/lib/analytics.ts — Core GA4 library. Exports initAnalytics(), trackPageView(),
grantAnalyticsConsent(), and typed event helpers (trackCTAClick, trackPhoneClick,
trackWhatsAppClick, trackLead, trackSearch, trackServiceView, trackFAQExpand,
trackPestView, trackOutboundClick). All calls become silent no-ops when
NEXT_PUBLIC_GA_MEASUREMENT_ID is unset, so dev builds stay clean. Respects
navigator.doNotTrack.
• src/components/site/analytics.tsx — Client component that initializes GA4 on first render,
tracks page views on every pathname / searchParams change, and renders the preconnect
hint. AnalyticsScript exports a server-rendered <script> tag for optimal load timing.
• src/components/site/cookie-consent.tsx — Privacy-first consent banner. Persists choice in
localStorage for 12 months. 'Accept all' grants analytics_storage via Consent Mode v2 update.
'Decline' denies. Includes link to FAQ for transparency. Only renders if GA4 is configured.
• .env.example — Documents the NEXT_PUBLIC_GA_MEASUREMENT_ID and
NEXT_PUBLIC_SITE_URL environment variables.
6.2 Consent Mode v2 compliance
Consent Mode v2 is configured with all six consent types: ad_storage, ad_user_data,
ad_personalization, analytics_storage, functionality_storage, security_storage. All default to
'denied' except the last two (which are required for the site to function). This is DPDP Act 2023
(India) and GDPR (EU) compliant: no PII is collected or transmitted to Google until the user
explicitly grants consent. When the user clicks 'Accept all' in the consent banner, or submits the
contact form (a meaningful engagement), grantAnalyticsConsent() is called, which issues a
gtag('consent', 'update', { analytics_storage: 'granted' }) call. Google's consent mode then
retroactively applies cookieless pings for any events that were queued before consent was
granted.
