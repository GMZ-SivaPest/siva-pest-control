   191→2. Website Audit
   192→The website audit evaluates structural integrity, navigation, performance signals, and
   193→mobile responsiveness. The Siva Pest Control site is built on Next.js 16 App Router with
   194→a multi-page architecture: 10 static routes plus dynamic routes for services (7), locations
   195→(3), and blog posts (6), totaling 26 URLs covered by an automatically-generated sitemap.
   196→All routes were verified to return HTTP 200 with no runtime errors.
   197→2.1 Site structure & navigation
   198→The site has been correctly refactored from a single-page application (SPA) with hash-style views
   199→to a true multi-page App Router architecture. Each major section (Services, Locations, Process,
   200→Pest Library, Industries, Blog, FAQ, Contact, About) lives at its own URL with its own metadata,
   201→and detail pages use Next.js's generateStaticParams + generateMetadata pattern for static
   202→generation and per-page SEO. The legacy Zustand navigation store has been preserved as a
   203→compatibility layer (via nav-bridge.tsx) so existing components continue to work, though new
   204→components should use Next.js <Link> directly.
   205→The desktop navigation bar offers a Services mega-menu (640px wide, glassmorphism) and a
   206→Locations dropdown (420px wide), both hover-triggered. A potential overflow concern exists at
   207→the 1024-1100px viewport range where the Services mega-menu could extend past the right edge
   208→of the viewport if the trigger is positioned near the right side of the navbar. The mobile menu is
   209→a right-side drawer with body-scroll lock and animated entrance. The footer is a comprehensive
   210→5-column grid with brand info, contact methods, three navigation columns, plus a locations
   211→strip and certifications bar.
   212→2.2 Performance indicators
   213→All images use next/image with the fill layout and explicit sizes attributes, which prevents layout
   214→shift and enables automatic format negotiation. The hero image and the technician composition
   215→image both use priority for Largest Contentful Paint (LCP) optimization. However, the
   216→about-page hero and the blog detail article hero image do not use priority — these should be
   217→added since they are the LCP element on their respective pages. The first three service cards on
   218→the /services page are above the fold and should also use priority.
   219→Framer Motion is used extensively for animations: scroll-reveal, staggered card entrances,
   220→mouse-tilt 3D, particle drift, shield pulse, and city-pin connections. All whileInView animations
   221→use viewport: { once: true }, preventing re-triggering on scroll-back. The hero's particle drift,
   222→shield pulse, and city-pin connections run indefinitely, which could impact battery life on
   223→low-end mobile devices. A <MotionConfig reducedMotion="user"> wrapper has been added to
   224→the root layout in this audit pass, and the hero now conditionally skips the heavy animations
   225→when prefers-reduced-motion is set.

   256→3. SEO Audit
   257→The SEO audit evaluates on-page factors, structured data, sitemap and robots
   258→configuration, technical SEO signals, local SEO readiness, content quality, and
   259→indexability. The site has a strong foundation — a PestControl JSON-LD schema, a
   260→comprehensive sitemap, and proper metadataBase — but several critical issues were
   261→identified and most have been fixed in this audit pass.
   262→3.1 On-page SEO
   263→Score: 5.5 / 10
   264→Page titles use the template pattern %s · Siva Pest Control correctly, and each page has a unique
   265→title. However, several page titles exceed the 60-character truncation point in Google SERPs (the
   266→services page title was 75 chars, industries 72 chars, blog 72 chars). The home meta description
   267→was 217 characters — well over the 150-160 optimal length. These have been shortened in this
   268→audit pass. Image alt text is present on all images but often just repeats the title (e.g.,
   269→alt={service.name}) rather than being descriptive; this should be improved for both accessibility
   270→and image SEO.
   271→Critical: Canonical URL bug (FIXED in this pass)
   272→The root layout.tsx set alternates.canonical to the homepage URL, and no child page overrode it.
   273→Next.js metadata merging caused every page to emit <link rel="canonical"
   274→href="https://www.sivapestcontrol.com">, telling Google all sub-pages were duplicates of the
   275→homepage. Sub-pages would have been dropped from the index. Fix applied: removed the root
   276→canonical and added per-page canonical URLs to all 13 routes.
   277→Internal linking was undermined by the use of <button onClick> for navigation in 11+
   278→components. Search engine crawlers can follow sitemap discoveries, but in-page link discovery
   279→is broken for blog posts, related services, related articles, and location detail CTAs. Each of these
   280→should be converted to <Link href> with descriptive anchor text.
   281→3.2 Structured data
   282→Score: 5.0 / 10 (improved to 7.5 after this pass)
   283→The root PestControl schema in layout.tsx is well-formed with name, address (3 cities), opening
   284→hours, aggregateRating, hasOfferCatalog, and sameAs socials. However, several improvements
   285→have been applied in this audit pass:
   286→• Per-service Service schema added — Each /services/[slug] route now emits a Service
   287→schema with name, description, provider, areaServed, offers (with INR price), and image.
   288→• Per-service FAQPage schema added — Each service's FAQ section is now emitted as
   289→FAQPage JSON-LD for rich-result eligibility.
   290→• Per-blog-post BlogPosting schema added — Each /blog/[slug] route now emits
   291→BlogPosting with headline, author, datePublished, image, publisher, and mainEntityOfPage.

   734→6. Google Analytics 4 Integration
   735→A complete, production-ready Google Analytics 4 (GA4) integration has been
   736→implemented in this audit pass. The integration follows Google's recommended
   737→patterns: lazy-loaded gtag.js, Consent Mode v2 with default-denied analytics storage,
   738→automatic page-view tracking on App Router route changes, typed custom event
   739→helpers for key conversions, and a privacy-first cookie consent banner with
   740→localStorage persistence.
   741→6.1 Architecture
   742→The integration consists of four files:
   743→• src/lib/analytics.ts — Core GA4 library. Exports initAnalytics(), trackPageView(),
   744→grantAnalyticsConsent(), and typed event helpers (trackCTAClick, trackPhoneClick,
   745→trackWhatsAppClick, trackLead, trackSearch, trackServiceView, trackFAQExpand,
   746→trackPestView, trackOutboundClick). All calls become silent no-ops when
   747→NEXT_PUBLIC_GA_MEASUREMENT_ID is unset, so dev builds stay clean. Respects
   748→navigator.doNotTrack.
   749→• src/components/site/analytics.tsx — Client component that initializes GA4 on first render,
   750→tracks page views on every pathname / searchParams change, and renders the preconnect
   751→hint. AnalyticsScript exports a server-rendered <script> tag for optimal load timing.
   752→• src/components/site/cookie-consent.tsx — Privacy-first consent banner. Persists choice in
   753→localStorage for 12 months. 'Accept all' grants analytics_storage via Consent Mode v2 update.
   754→'Decline' denies. Includes link to FAQ for transparency. Only renders if GA4 is configured.
   755→• .env.example — Documents the NEXT_PUBLIC_GA_MEASUREMENT_ID and
   756→NEXT_PUBLIC_SITE_URL environment variables.
   757→6.2 Consent Mode v2 compliance
   758→Consent Mode v2 is configured with all six consent types: ad_storage, ad_user_data,
   759→ad_personalization, analytics_storage, functionality_storage, security_storage. All default to
   760→'denied' except the last two (which are required for the site to function). This is DPDP Act 2023
   761→(India) and GDPR (EU) compliant: no PII is collected or transmitted to Google until the user
   762→explicitly grants consent. When the user clicks 'Accept all' in the consent banner, or submits the
   763→contact form (a meaningful engagement), grantAnalyticsConsent() is called, which issues a
   764→gtag('consent', 'update', { analytics_storage: 'granted' }) call. Google's consent mode then
   765→retroactively applies cookieless pings for any events that were queued before consent was
   766→granted.
