   187→2. Website Audit
   188→The website audit evaluates structural integrity, navigation, performance signals, and
   189→mobile responsiveness. The Siva Pest Control site is built on Next.js 16 App Router with
   190→a multi-page architecture: 10 static routes plus dynamic routes for services (7), locations
   191→(3), and blog posts (6), totaling 26 URLs covered by an automatically-generated sitemap.
   192→All routes were verified to return HTTP 200 with no runtime errors.
   193→2.1 Site structure & navigation
   194→The site has been correctly refactored from a single-page application (SPA) with hash-style views
   195→to a true multi-page App Router architecture. Each major section (Services, Locations, Process,
   196→Pest Library, Industries, Blog, FAQ, Contact, About) lives at its own URL with its own metadata,
   197→and detail pages use Next.js's generateStaticParams + generateMetadata pattern for static
   198→generation and per-page SEO. The legacy Zustand navigation store has been preserved as a
   199→compatibility layer (via nav-bridge.tsx) so existing components continue to work, though new
   200→components should use Next.js <Link> directly.
   201→The desktop navigation bar offers a Services mega-menu (640px wide, glassmorphism) and a
   202→Locations dropdown (420px wide), both hover-triggered. A potential overflow concern exists at
   203→the 1024-1100px viewport range where the Services mega-menu could extend past the right edge
   204→of the viewport if the trigger is positioned near the right side of the navbar. The mobile menu is
   205→a right-side drawer with body-scroll lock and animated entrance. The footer is a comprehensive
   206→5-column grid with brand info, contact methods, three navigation columns, plus a locations
   207→strip and certifications bar.
   208→2.2 Performance indicators
   209→All images use next/image with the fill layout and explicit sizes attributes, which prevents layout
   210→shift and enables automatic format negotiation. The hero image and the technician composition
   211→image both use priority for Largest Contentful Paint (LCP) optimization. However, the
   212→about-page hero and the blog detail article hero image do not use priority — these should be
   213→added since they are the LCP element on their respective pages. The first three service cards on
   214→the /services page are above the fold and should also use priority.
   215→Framer Motion is used extensively for animations: scroll-reveal, staggered card entrances,
   216→mouse-tilt 3D, particle drift, shield pulse, and city-pin connections. All whileInView animations
   217→use viewport: { once: true }, preventing re-triggering on scroll-back. The hero's particle drift,
   218→shield pulse, and city-pin connections run indefinitely, which could impact battery life on
   219→low-end mobile devices. A <MotionConfig reducedMotion="user"> wrapper has been added to
   220→the root layout in this audit pass, and the hero now conditionally skips the heavy animations
   221→when prefers-reduced-motion is set.

   250→3. SEO Audit
   251→The SEO audit evaluates on-page factors, structured data, sitemap and robots
   252→configuration, technical SEO signals, local SEO readiness, content quality, and
   253→indexability. The site has a strong foundation — a PestControl JSON-LD schema, a
   254→comprehensive sitemap, and proper metadataBase — but several critical issues were
   255→identified and most have been fixed in this audit pass.
   256→3.1 On-page SEO
   257→Score: 5.5 / 10
   258→Page titles use the template pattern %s · Siva Pest Control correctly, and each page has a unique
   259→title. However, several page titles exceed the 60-character truncation point in Google SERPs (the
   260→services page title was 75 chars, industries 72 chars, blog 72 chars). The home meta description
   261→was 217 characters — well over the 150-160 optimal length. These have been shortened in this
   262→audit pass. Image alt text is present on all images but often just repeats the title (e.g.,
   263→alt={service.name}) rather than being descriptive; this should be improved for both accessibility
   264→and image SEO.
   265→Critical: Canonical URL bug (FIXED in this pass)
   266→The root layout.tsx set alternates.canonical to the homepage URL, and no child page overrode it.
   267→Next.js metadata merging caused every page to emit <link rel="canonical"
   268→href="https://www.sivapestcontrol.com">, telling Google all sub-pages were duplicates of the
   269→homepage. Sub-pages would have been dropped from the index. Fix applied: removed the root
   270→canonical and added per-page canonical URLs to all 13 routes.
   271→Internal linking was undermined by the use of <button onClick> for navigation in 11+
   272→components. Search engine crawlers can follow sitemap discoveries, but in-page link discovery
   273→is broken for blog posts, related services, related articles, and location detail CTAs. Each of these
   274→should be converted to <Link href> with descriptive anchor text.
   275→3.2 Structured data
   276→Score: 5.0 / 10 (improved to 7.5 after this pass)
   277→The root PestControl schema in layout.tsx is well-formed with name, address (3 cities), opening
   278→hours, aggregateRating, hasOfferCatalog, and sameAs socials. However, several improvements
   279→have been applied in this audit pass:
   280→• Per-service Service schema added — Each /services/[slug] route now emits a Service
   281→schema with name, description, provider, areaServed, offers (with INR price), and image.
   282→• Per-service FAQPage schema added — Each service's FAQ section is now emitted as
   283→FAQPage JSON-LD for rich-result eligibility.
   284→• Per-blog-post BlogPosting schema added — Each /blog/[slug] route now emits
   285→BlogPosting with headline, author, datePublished, image, publisher, and mainEntityOfPage.

   717→6. Google Analytics 4 Integration
   718→A complete, production-ready Google Analytics 4 (GA4) integration has been
   719→implemented in this audit pass. The integration follows Google's recommended
   720→patterns: lazy-loaded gtag.js, Consent Mode v2 with default-denied analytics storage,
   721→automatic page-view tracking on App Router route changes, typed custom event
   722→helpers for key conversions, and a privacy-first cookie consent banner with
   723→localStorage persistence.
   724→6.1 Architecture
   725→The integration consists of four files:
   726→• src/lib/analytics.ts — Core GA4 library. Exports initAnalytics(), trackPageView(),
   727→grantAnalyticsConsent(), and typed event helpers (trackCTAClick, trackPhoneClick,
   728→trackWhatsAppClick, trackLead, trackSearch, trackServiceView, trackFAQExpand,
   729→trackPestView, trackOutboundClick). All calls become silent no-ops when
   730→NEXT_PUBLIC_GA_MEASUREMENT_ID is unset, so dev builds stay clean. Respects
   731→navigator.doNotTrack.
   732→• src/components/site/analytics.tsx — Client component that initializes GA4 on first render,
   733→tracks page views on every pathname / searchParams change, and renders the preconnect
   734→hint. AnalyticsScript exports a server-rendered <script> tag for optimal load timing.
   735→• src/components/site/cookie-consent.tsx — Privacy-first consent banner. Persists choice in
   736→localStorage for 12 months. 'Accept all' grants analytics_storage via Consent Mode v2 update.
   737→'Decline' denies. Includes link to FAQ for transparency. Only renders if GA4 is configured.
   738→• .env.example — Documents the NEXT_PUBLIC_GA_MEASUREMENT_ID and
   739→NEXT_PUBLIC_SITE_URL environment variables.
   740→6.2 Consent Mode v2 compliance
   741→Consent Mode v2 is configured with all six consent types: ad_storage, ad_user_data,
   742→ad_personalization, analytics_storage, functionality_storage, security_storage. All default to
   743→'denied' except the last two (which are required for the site to function). This is DPDP Act 2023
   744→(India) and GDPR (EU) compliant: no PII is collected or transmitted to Google until the user
   745→explicitly grants consent. When the user clicks 'Accept all' in the consent banner, or submits the
   746→contact form (a meaningful engagement), grantAnalyticsConsent() is called, which issues a
   747→gtag('consent', 'update', { analytics_storage: 'granted' }) call. Google's consent mode then
   748→retroactively applies cookieless pings for any events that were queued before consent was
   749→granted.
