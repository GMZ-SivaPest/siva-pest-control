   188→The website audit evaluates structural integrity, navigation, performance signals, and

   195→to a true multi-page App Router architecture. Each major section (Services, Locations, Process,
   196→Pest Library, Industries, Blog, FAQ, Contact, About) lives at its own URL with its own metadata,
   197→and detail pages use Next.js's generateStaticParams + generateMetadata pattern for static
   198→generation and per-page SEO. The legacy Zustand navigation store has been preserved as a
   199→compatibility layer (via nav-bridge.tsx) so existing components continue to work, though new
   200→components should use Next.js <Link> directly.

   204→of the viewport if the trigger is positioned near the right side of the navbar. The mobile menu is
   205→a right-side drawer with body-scroll lock and animated entrance. The footer is a comprehensive
   206→5-column grid with brand info, contact methods, three navigation columns, plus a locations
   207→strip and certifications bar.

   209→All images use next/image with the fill layout and explicit sizes attributes, which prevents layout
   210→shift and enables automatic format negotiation. The hero image and the technician composition
   211→image both use priority for Largest Contentful Paint (LCP) optimization. However, the
   212→about-page hero and the blog detail article hero image do not use priority — these should be
   213→added since they are the LCP element on their respective pages. The first three service cards on
